## 检查并改进响应拦截器

### 1. 问题分析
目前响应拦截器的实现是：
- 直接返回后端原始数据，让 service 层处理
- 没有特别处理 204 状态码

### 2. 需求分析
- 删除规范的 API 文档中返回的是 204 状态码
- 用户提供的截图显示返回的是 200 状态码
- 需要确保响应拦截器正确处理所有状态码，包括 204 状态码

### 3. 实现计划

#### 3.1 检查响应拦截器的实现
- 查看 `responseInterceptor` 函数如何处理响应数据
- 查看 `responseInterceptorError` 函数如何处理错误

#### 3.2 改进响应拦截器
- 添加对 204 状态码的处理
- 确保 204 状态码返回正确的格式，让 service 层可以处理

#### 3.3 测试响应拦截器
- 测试删除规范功能，确保响应拦截器正确处理 204 状态码
- 测试其他 API 请求，确保响应拦截器不影响其他功能

### 4. 技术实现

#### 4.1 响应拦截器修改
- `response.js`：
  - 修改 `responseInterceptor` 函数，添加对 204 状态码的处理
  - 确保 204 状态码返回正确的格式，包含 code、message 和 data 字段

### 5. 预期结果
- 响应拦截器正确处理 204 状态码
- 204 状态码返回格式与其他状态码一致，包含 code、message 和 data 字段
- 删除规范功能正常工作
- 其他 API 请求不受影响

### 6. 风险评估
