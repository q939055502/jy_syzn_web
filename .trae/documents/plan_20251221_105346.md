## 修复获取用户信息失败问题

### 目标

解决获取用户信息返回 401 未授权错误的问题，确保登录流程正常工作。

### 分析

1. **API 文档要求**：登录接口 `/api/auth/token` 要求使用 `application/x-www-form-urlencoded` 格式，而当前代码使用 `application/json` 格式。
2. **当前实现问题**：

   * 登录请求使用 JSON 格式，导致后端无法正确解析，返回 422 错误

   * 没有正确获取到 token，导致后续请求用户信息时返回 401 错误

   * 响应拦截器没有对登录接口的特殊响应格式进行处理

### 解决方案

1. **修改登录请求格式**：

   * 将 `login` 函数中的请求格式改为 `application/x-www-form-urlencoded`

   * 使用 `URLSearchParams` 处理请求数据
2. **优化响应处理**：

   * 确保响应拦截器能正确处理不同格式的响应

   * 登录接口返回的是直接的 token 对象，不是统一格式，需要特殊处理
3. **验证 token 存储和使用**：

   * 确保登录成功后 token 被正确存储到本地存储和 Pinia store

   * 确保请求拦截器能正确从本地存储获取 token 并添加到请求头

### 步骤

1. **修改登录函数**：

   * 文件：`src/api/user.js`

   * 修改 `login` 函数，使用 `URLSearchParams` 格式化请求数据
2. **优化响应拦截器**：

   * 文件：`src/api/interceptors/response.js`

   * 修改响应拦截器，正确处理登录接口的特殊响应格式
3. **检查请求拦截器**：

   * 文件：`src/api/interceptors/request.js`

   * 确保请求拦截器正确添加 token 到请求头
4. **测试登录流程**：

   * 运行项目，测试登录功能

   * 验证登录成功后能正确获取用户信息

### 预期结果

* 登录请求使用正确的 `application/x-www-form-urlencoded` 格式

* 登录成功后能正确获取 token 并存储

* 请求用户信息时能正确添加 token 到请求头

* 获取用户信息成功，不再返回 401 错误
