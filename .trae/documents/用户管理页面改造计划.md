# 用户管理页面改造计划

## 1. 改造背景

- API文档已更新，包含获取用户信息的接口
- 当前用户管理页面使用静态数据，需要改为从后端获取
- 需要保持规范化的层级结构，避免业务逻辑写在组件内
- 表头需要调整为更合适的格式

## 2. 改造目标

- 从后端API获取用户列表数据
- 保持代码的规范化层级结构
- 调整表头为更合适的格式
- 确保组件能正确响应主题变化

## 3. 改造方案

### 3.1 API层改造

在 `src/api/user.js` 中添加获取用户列表的API方法：
- 添加 `getUserList` 方法，调用 `/api/admin/users` 接口
- 支持分页参数 `page` 和 `limit`

### 3.2 服务层改造

在 `src/services/userService.js` 中添加对应的服务方法：
- 添加 `getUserList` 方法，调用API层的 `getUserList` 方法
- 处理响应数据，返回统一格式

### 3.3 状态管理改造

在 `src/stores/user.js` 中添加用户列表的状态和方法：
- 添加 `userList` 状态存储用户列表
- 添加 `totalUsers` 状态存储总用户数
- 添加 `getUserList` 方法获取用户列表
- 添加 `updateUserStatus` 方法更新用户状态
- 添加 `deleteUser` 方法删除用户

### 3.4 组件改造

修改 `src/views/UserManagement.vue`：
- 从 `useUserStore` 获取用户列表数据
- 调整表头为更合适的格式（ID, 用户名, 姓名, 超级管理员, 状态, 在线状态, 创建时间, 操作）
- 实现分页功能
- 实现搜索功能
- 实现状态切换功能
- 实现编辑和删除功能
- 确保组件能正确响应主题变化

## 4. 改造步骤

1. **API层改造**：添加获取用户列表的API方法
2. **服务层改造**：添加对应的服务方法
3. **状态管理改造**：添加用户列表的状态和方法
4. **组件改造**：修改UserManagement.vue组件
5. **测试验证**：确保功能正常，主题响应正确

## 5. 预期效果

- 用户列表数据从后端API获取
- 保持了规范化的层级结构
- 表头格式更合适
- 组件能正确响应主题变化
- 支持分页、搜索、状态切换、编辑和删除功能

## 6. 技术要点

- 使用Pinia进行状态管理
- 使用Axios进行API调用
- 遵循分层架构原则
- 支持主题响应
- 实现完整的CRUD功能
