# 状态管理拆分建议

## 1. 问题分析

当前 `user.js` store 包含了两种不同类型的状态：
- **用户认证状态**：`userInfo`、`isLoggedIn`、`token`、`refreshToken` 等
- **用户管理状态**：`userList`、`totalUsers`、`pagination` 等

这种混合设计不符合单一职责原则，会导致状态管理变得复杂，不利于维护和扩展。

## 2. 最佳实践参考

根据前端状态管理的最佳实践，通常会将状态按照功能领域进行拆分：
- **认证状态（Auth）**：处理登录、登出、令牌刷新等用户认证相关功能
- **资源管理状态（如 UserManagement）**：处理用户列表、增删改查等管理功能

## 3. 拆分方案

### 3.1 Store 层拆分

#### 3.1.1 创建 `auth.js` store

- **状态**：用户认证相关状态
  - `userInfo`：当前登录用户信息
  - `isLoggedIn`：登录状态
  - `token`：访问令牌
  - `refreshToken`：刷新令牌
  - `isLoading`：加载状态
  - `error`：错误信息

- **Actions**：
  - `login`：登录
  - `logout`：登出
  - `refreshToken`：刷新令牌
  - `fetchUserInfo`：获取当前用户信息
  - `checkLoginStatus`：检查登录状态

#### 3.1.2 创建 `userManagement.js` store

- **状态**：用户管理相关状态
  - `userList`：用户列表
  - `totalUsers`：总用户数
  - `pagination`：分页信息
  - `isLoading`：加载状态
  - `error`：错误信息

- **Actions**：
  - `fetchUserList`：获取用户列表
  - `updateUserStatus`：更新用户状态
  - `deleteUser`：删除用户
  - `batchDeleteUsers`：批量删除用户
  - `updatePagination`：更新分页信息
  - `resetUserListState`：重置用户列表状态

### 3.2 Service 层拆分

#### 3.2.1 创建 `authService.js`

- **功能**：处理用户认证相关业务逻辑
- **方法**：
  - `login`：登录
  - `logout`：登出
  - `refreshToken`：刷新令牌
  - `getUserInfo`：获取当前用户信息
  - `checkLoginStatus`：检查登录状态

#### 3.2.2 创建 `userManagementService.js`

- **功能**：处理用户管理相关业务逻辑
- **方法**：
  - `getUserList`：获取用户列表
  - `updateUserStatus`：更新用户状态
  - `deleteUser`：删除用户

### 3.3 API 层拆分

根据需要，可以将 `user.js` API 拆分为 `auth.js` 和 `userManagement.js`，或者保持不变，由服务层进行调用。

## 4. 代码结构

```
src/
├── stores/
│   ├── auth.js          # 用户认证状态管理
│   ├── userManagement.js # 用户管理状态管理
│   └── permission.js     # 权限管理状态管理
├── services/
│   ├── authService.js    # 用户认证服务
│   ├── userManagementService.js # 用户管理服务
│   └── permissionService.js # 权限管理服务
└── api/
    ├── auth.js          # 用户认证 API（可选拆分）
    ├── user.js          # 用户管理 API（可选拆分）
    └── permission.js     # 权限管理 API
```

## 5. 拆分好处

1. **职责单一**：每个 store 只负责一个功能领域，便于维护和理解
2. **按需加载**：可以根据页面需求按需导入对应的 store，提高性能
3. **减少耦合**：不同功能领域的状态相互独立，减少状态间的耦合
4. **便于测试**：每个 store 可以单独进行测试，提高测试效率
5. **扩展性好**：新增功能时可以创建新的 store，不影响现有代码
6. **清晰的命名**：通过文件名就能明确知道 store 的功能

## 6. 迁移步骤

1. 创建新的 store 文件 `auth.js` 和 `userManagement.js`
2. 将 `user.js` 中的状态和 actions 按照功能拆分到新文件中
3. 创建新的服务文件 `authService.js` 和 `userManagementService.js`
4. 将 `userService.js` 中的方法拆分到新文件中
5. 更新组件中的导入和使用
6. 测试所有功能是否正常

## 7. 总结

将状态管理按照功能领域进行拆分是前端状态管理的最佳实践，可以提高代码的可维护性、可扩展性和可测试性。建议将当前的 `user.js` store 拆分为 `auth.js` 和 `userManagement.js`，分别管理用户认证和用户管理功能。
